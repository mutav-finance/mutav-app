# Guarantee lifecycle — specification

The lifecycle of one guarantee, from draft to closure, as enforced by the code on `main` @ `a175516` (2026-09-29). Every rule below cites the file and line that enforces it and the test that proves it, so a reader can verify each claim without trusting this document. Where the shipped code deviates from the protocol-level scenarios document that seeded the design, § 10 says so.

Diagram: [`guarantee-lifecycle.html`](guarantee-lifecycle.html) (the seven states and every edge, labelled by actor). Design record: [ADR 0007](decisions/0007-lease-guarantee-split.md). Domain code: [`convex/guarantees/`](../../convex/guarantees/), [`convex/delinquencies/`](../../convex/delinquencies/), [`convex/coverOperations/`](../../convex/coverOperations/).

The diagrams (`system-architecture.html`, `guarantee-lifecycle.html`) are labelled in Portuguese; this document is the English reference.

## 1. Scope

A **guarantee** is what Mutav sells: the rental-guarantee obligation on one lease, with its own immutable pricing snapshot and its own coverage capacity. A **lease** is the rental relationship it is written against; one lease takes many guarantees over its life, at most one of them open (`leases.openGuaranteeId`). A **delinquency notice** is one reported missed rent; notices are the events that move a guarantee through its default states.

Two programme terms recur below. The **pilot** is the first production phase: low volume, with every default and cover decision taken by Mutav compliance staff ([ADR 0004](decisions/0004-pilot-cover-default-coverage-draw.md)). **Stage 2** is the follow-on phase — pieces that are designed but not yet built, such as the wallet-connected investor app; the diagrams draw them dashed.

This document covers the guarantee state machine, the notice state machine, how the two are coupled, the cover ledger, the capacity policy, the single write path, and the audit trail. It does not cover pricing (products / `terms`), the agency UI, or the on-chain reserve draw (see [ADR 0004](decisions/0004-pilot-cover-default-coverage-draw.md) and `mutav-app#286`).

## 2. States

`GUARANTEE_STATE` — [`convex/guarantees/machine.ts:4-12`](../../convex/guarantees/machine.ts). The schema literal union mirrors it at [`convex/schema.ts:14-22`](../../convex/schema.ts).

| State              | Meaning                                                                                                                                                                                                                           | In force? | Capital effect                                                                                                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `drafted`          | Created and priced; the lease has not started. `capacity` already holds the priced ceiling.                                                                                                                                       | no        | none — `reservedCents` must be `0` to activate                                                                                                               |
| `active`           | Lease running, rent current.                                                                                                                                                                                                      | yes       | counts toward platform exposure                                                                                                                              |
| `in_arrears`       | Entered when a notice is opened on an `active` guarantee; normally at least one notice is `open`. A notice resolved as `stale` does not move the guarantee, so it can sit here with no open notice.                               | yes       | no change — arrears alone never moves capacity                                                                                                               |
| `default_verified` | Compliance verified a notice (`staffVerifyDefault`); the default is real, nothing paid yet.                                                                                                                                       | yes       | no change — **verify ≠ pay**                                                                                                                                 |
| `cover_committed`  | Compliance committed cover against a verified notice; `reservedCents` holds the applied draws. The off-chain payout is tracked in the `coverOperations` ledger (§ 6.3); the recourse claim against the tenant is not tracked yet. | yes       | `reservedCents` holds the sum of every applied draw                                                                                                          |
| `in_eviction`      | Eviction proceedings under way; the only exit is `closed(eviction)`.                                                                                                                                                              | yes       | reserved cents stay held                                                                                                                                     |
| `closed`           | Terminal. Carries a `closure { reason, closedAt, note? }`.                                                                                                                                                                        | no        | only `close(dispute_reversal)` moves `capacity` (releases it); every other reason leaves it ([`mutations.ts:191-195`](../../convex/guarantees/mutations.ts)) |

- **Insured states** = `active, in_arrears, default_verified, cover_committed, in_eviction` — `INSURED_STATES`, [`domain.ts:61-67`](../../convex/guarantees/domain.ts). They are not lexically contiguous, so every aggregate read iterates the list rather than a key range.
- **Terminal states** = `{ closed }` — `TERMINAL_STATES`, [`machine.ts:26`](../../convex/guarantees/machine.ts).
- `activatedAt` is stamped once, on the first entry to `active` ([`transitions.ts:136-138`](../../convex/guarantees/transitions.ts)); a cure that returns to `active` does not reset it.

## 3. Transition matrix

`ALLOWED_TRANSITIONS` — [`machine.ts:37-60`](../../convex/guarantees/machine.ts). This map is the enforcement point; nothing else in the codebase decides whether a move is legal.

| from →             | `active` | `in_arrears` | `default_verified` | `cover_committed` | `in_eviction` | `closed` |
| ------------------ | :------: | :----------: | :----------------: | :---------------: | :-----------: | :------: |
| `drafted`          |    ✓     |              |                    |                   |               |    ✓     |
| `active`           |          |      ✓       |                    |                   |       ✓       |    ✓     |
| `in_arrears`       |    ✓     |              |         ✓          |                   |       ✓       |    ✓     |
| `default_verified` |    ✓     |              |                    |         ✓         |       ✓       |    ✓     |
| `cover_committed`  |    ✓     |      ✓       |                    |                   |       ✓       |    ✓     |
| `in_eviction`      |          |              |                    |                   |               |    ✓     |
| `closed`           |          |              |                    |                   |               |          |

Three deliberate choices a reader may not expect:

1. **`cover_committed` is not terminal in the machine.** The edges `cover_committed → active` (tenant cures after cover) and `cover_committed → in_arrears` (a later rent slips) are legal in the machine and tested ([`machine.test.ts:153`](../../convex/guarantees/machine.test.ts)); no mutation performs them yet — they arrive with the recourse-receivable ledger. Today an agency disposition returns to `active` only from `in_arrears` (`AGENCY_RETURN_TO_ACTIVE_FROM`, `delinquencies/mutations.ts:90`), a staff dismissal only from `in_arrears` / `default_verified` (`:101-104`), `openNotice` leaves a non-`active` guarantee in its state (`:280`), and recording cover only ever moves `default_verified → cover_committed` ([`coverOperations/mutations.ts:219-227`](../../convex/coverOperations/mutations.ts)). A guarantee under cover leaves it only by eviction or close.
2. **Any activated state may enter eviction.** Eviction is a legal fact, not a stage of the default ladder.
3. **Any activated state may close.** End of lease, rescission, abandonment or death can happen while a notice is open; the close reason, not the state, records why.

`assertTransition(from, to)` — [`machine.ts:69-100`](../../convex/guarantees/machine.ts) — returns a `Result`, never throws, and checks in this order:

| Code                 | When                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| `SELF_TRANSITION`    | `from === to` (any state, incl. terminal) — this is the replay guard |
| `TERMINAL_STATE`     | `from` is `closed`                                                   |
| `ILLEGAL_TRANSITION` | edge not in `ALLOWED_TRANSITIONS`                                    |

## 4. Close reasons

A close is a transition **plus** a reason, and the reason is gated by the state it comes from. `CLOSE_REASON` and `CLOSE_REASON_ALLOWED_FROM` — [`machine.ts:102-154`](../../convex/guarantees/machine.ts).

| Reason                    | Allowed from                          | Meaning                                                                                           |
| ------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `end_of_lease`            | any activated state                   | the lease ran its term                                                                            |
| `rescission`              | any activated state                   | the parties ended the lease early                                                                 |
| `abandonment`             | any activated state                   | the tenant left without notice                                                                    |
| `death`                   | any activated state                   | the tenant died                                                                                   |
| `eviction`                | `in_eviction` only                    | the eviction concluded                                                                            |
| `dispute_reversal`        | `default_verified`, `cover_committed` | a verified default was overturned                                                                 |
| `canceled_pre_activation` | `drafted` only                        | a draft is **canceled**, never ended ([`machine.ts:134-137`](../../convex/guarantees/machine.ts)) |

"Any activated state" = `ENDED_FROM_ANY_ACTIVATED_STATE` = the five insured states ([`machine.ts:138-144`](../../convex/guarantees/machine.ts)).

`assertClose(from, reason)` ([`machine.ts:160-184`](../../convex/guarantees/machine.ts)) returns `TERMINAL_STATE` or `REASON_NOT_ALLOWED_FROM_STATE`. It does not call `assertTransition` itself; the write path runs both in sequence — `assertTransition(from, "closed")` at `transitions.ts:88`, then `assertClose` at `transitions.ts:108-113`. Two further checks live in the write path ([`transitions.ts:93-107`](../../convex/guarantees/transitions.ts)): a move to `closed` without a `closure` → `CLOSURE_REQUIRED`; a `closure` on any other move → `CLOSURE_NOT_ALLOWED`. Full `(from, reason)` matrix: [`close.test.ts`](../../convex/guarantees/close.test.ts).

## 5. The single write path

Every change to `guarantees.status` goes through `applyGuaranteeTransition`, with two exceptions that insert rather than move: `create` inserts a row directly in `drafted` ([`useCases.ts:1068`](../../convex/guarantees/useCases.ts)), and the dev seed inserts rows in their seeded state ([`convex/seed.ts:522`](../../convex/seed.ts)). `applyGuaranteeTransition` lives at [`convex/guarantees/transitions.ts:84-190`](../../convex/guarantees/transitions.ts). It is not a Convex function; the public mutations compose it **inside their own transaction**. From its doc comment:

> an error `Result` is returned before the first write, so a refused call leaves the transaction untouched. Once a write has happened, a failure throws and the whole transaction rolls back.

Ordered side effects, exactly as coded:

| #   | Step                                                                                    | Where                    |
| --- | --------------------------------------------------------------------------------------- | ------------------------ |
| 1   | `assertTransition(from, to)`                                                            | `transitions.ts:88`      |
| 2   | closure presence: `CLOSURE_REQUIRED` / `CLOSURE_NOT_ALLOWED`                            | `transitions.ts:93-107`  |
| 3   | `assertClose(from, reason)` when closing                                                | `transitions.ts:108-113` |
| 4   | `isValidCapacity` on any supplied capacity (refused, never repaired)                    | `transitions.ts:114-120` |
| 5   | `db.patch` — `status`, `closure`, `activatedAt` (first `active` only), `capacity`       | `transitions.ts:125-140` |
| 6   | rewrite the three aggregates (`guaranteesByState`, `…Platform`, `insuredCentsPlatform`) | `transitions.ts:142-144` |
| 7   | insert a `guaranteeHistory` row with `transition { from, to, closeReason? }`            | `transitions.ts:146-157` |
| 8   | append `guarantee.transitioned` to the hash-chained audit log                           | `transitions.ts:159-174` |
| 9   | when closing, null `leases.openGuaranteeId` if it points at this row                    | `transitions.ts:176-183` |

Steps 1–4 write nothing; steps 5–9 are one Convex transaction. Capacity changes outside a status move (a cover draw, a reversal release) go through `writeCapacity` ([`transitions.ts:439-449`](../../convex/guarantees/transitions.ts)), which patches the row and rewrites the aggregates together. The scheduler is never used for a lifecycle move ([ADR 0007 § 5](decisions/0007-lease-guarantee-split.md)), so a notice and the guarantee state it implies cannot disagree. Proven at [`transitions.test.ts`](../../convex/guarantees/transitions.test.ts) "machine composition" and [`scenarios.test.ts`](../../convex/guarantees/scenarios.test.ts) "guard before patch".

## 6. Who may move what

Two actors move a guarantee: the **agency** (any member of the guarantee's agency, via `mutationWithAgencyScope` — [`convex/lib/auth.ts:132`](../../convex/lib/auth.ts) — or, for `markResolved` / `markCanceled`, a bare `mutation` with an inline `assertAgencyAccess` on the notice's agency, [`delinquencies/mutations.ts:352, 462`](../../convex/delinquencies/mutations.ts)) and **Mutav staff at `compliance` or above** (`mutationWithMutavRole({ minRole: "compliance" })` — [`auth.ts:213`](../../convex/lib/auth.ts); ladder `support < compliance < admin`, [`convex/mutavStaff/domain.ts:31`](../../convex/mutavStaff/domain.ts)). Authority is narrower than the machine: some legal edges have no caller today. On the UI side, the agency app calls `cancelDraft`, `openNotice` and `markCanceled`, and the admin `/defaults` screen calls `staffVerifyDefault`, `staffRecordCover`, `staffRecordCoverBatch`, `staffMarkCanceledByDismissal` and `staffMarkCoverExecuted`. No app calls anything in `convex/guarantees/mutations.ts` yet — in particular **no admin UI calls `guarantees.mutations.close`**, so `close(dispute_reversal)` is reachable only through the mutation itself (Convex dashboard / CLI) or seeded data ([`convex/seed.ts:3205`](../../convex/seed.ts)) — the gap recorded in [`docs/grants/instawards-status.md`](../grants/instawards-status.md).

### 6.3 Cover ledger — `convex/coverOperations/mutations.ts`

Committing cover writes a row in the `coverOperations` ledger ([`schema.ts:643-673`](../../convex/schema.ts)), resolves the notice, reserves capacity and, on the first draw of an episode, moves the guarantee — all in one transaction. The payout itself stays **manual and off-chain**: the ledger records that Mutav owes it and, later, that it left. The on-chain `cover_default` draw from the reserve is not built ([ADR 0004](decisions/0004-pilot-cover-default-coverage-draw.md), `mutav-app#286`).

**Two phases, one direction** — `COVER_OPERATION_STATUS` `recorded → executed` ([`coverOperations/domain.ts:15-18`](../../convex/coverOperations/domain.ts)). `recorded` means compliance committed cover and capacity is reserved; `executed` means the off-chain payout to the landlord has left and carries its payment reference. There is no way back from `executed`.

| Mutation                 | Actor | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Code   |
| ------------------------ | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `staffRecordCover`       | staff | One verified notice: notice `verified → resolved(cover_committed)`; reserves capacity for its `updatedAmountCents` (§ 7); `default_verified → cover_committed` on the first draw, later draws keep state; inserts one ledger row in `recorded`. Audit `delinquency.resolved_by_cover` and `cover_operation.recorded`.                                                                                                                                     | `:319` |
| `staffRecordCoverBatch`  | staff | Up to `MAX_COVER_BATCH_SIZE` = 25 notices ([`domain.ts:45`](../../convex/coverOperations/domain.ts)), **all or nothing**: every notice is planned read-only before any is written (`:387-422`), so one refusal refuses the whole batch and names the offending `noticePublicId`. One operation per notice — so still one per guarantee per period — under a shared `batchId`. Also refuses `EMPTY_BATCH`, `BATCH_TOO_LARGE`, `DUPLICATE_NOTICE_IN_BATCH`. | `:363` |
| `staffMarkCoverExecuted` | staff | `recorded → executed`. **Requires** a non-blank off-chain `paymentReference` (`PAYMENT_REFERENCE_REQUIRED`, `:465-472`); refuses a second execution (`COVER_ALREADY_EXECUTED`, `:485-491`). Stores `execution { executedAt, executedByUserId, paymentReference, note? }`. Audit `cover_operation.executed`.                                                                                                                                               | `:458` |

A cover is refused, before any write, when the notice is missing, is not itself `verified` (`NOTICE_NOT_VERIFIED`), its guarantee is not `default_verified` / `cover_committed` (`GUARANTEE_TRANSITION_REFUSED`), the guarantee's capacity is already invalid (`CAPACITY_INVARIANT_BROKEN`), or the amount is not a non-negative integer (`INVALID_AMOUNT`) — `planCover`, [`coverOperations/mutations.ts:89-172`](../../convex/coverOperations/mutations.ts). Any write after planning that fails throws, rolling back the whole transaction, batch included (`commitCover`, `:192-302`).

- **Idempotency key.** ADR 0004's one draw per guarantee per billing month: `(guaranteeId, coveragePeriod)`, where `coveragePeriod` is the month of the notice's `rentDueDate` as `YYYY-MM` (`coveragePeriodOf`, [`domain.ts:58-65`](../../convex/coverOperations/domain.ts)). A second cover for the same key is `COVER_ALREADY_RECORDED` — checked against the ledger through `by_guarantee_period` (`:154-169`) and, inside a batch, against the batch itself (`:406-420`). The row, not the batch, is the idempotency unit.
- **Notice ↔ ledger link.** The notice's `resolution` carries `coverOperationId`, `coverOperationPublicId` and `appliedCoverCents` ([`schema.ts:609-619`](../../convex/schema.ts); written at `:245-258`). The ledger row carries `requestedCents` (the notice's amount at cover time) and `appliedCents` (what capacity allowed).
- **Read side.** `listAwaitingPayout` ([`coverOperations/useCases.ts:61`](../../convex/coverOperations/useCases.ts)) lists `recorded` rows across agencies, oldest first, for the admin "payouts awaiting execution" panel.

### 6.4 Notice state machine — `convex/delinquencies/machine.ts`

Statuses `open, verified, resolved, canceled` (`:18-23`); terminal = `resolved, canceled` (`:39-42`); edges `open → verified | resolved | canceled`, `verified → resolved | canceled` (`:53-60`); the same three error codes as the guarantee machine (`:62-65`). Value objects in [`delinquencies/domain.ts`](../../convex/delinquencies/domain.ts): resolution kinds `tenant_cured, cover_committed, staff_dispute, stale`; cancellation reasons `agency_withdrew, staff_dismissed, duplicate, data_error`; evidence sources `agency_reported, tenant_confirmed, bank_attested, onchain_observed, system_scheduled` (only `agency_reported` is accepted by `openNotice` today, `mutations.ts:184-192`).

## 7. Capacity policy

Policy **C** ([ADR 0007 § 6](decisions/0007-lease-guarantee-split.md)). The design weighed three capacity policies: A burns capacity permanently on cover, B restores it when the tenant repays, and C reserves it on cover, releases it on repayment and burns it only on write-off. The code implements C's reserve half, plus an exact release when a verified default is reversed. Row shape `guarantees.capacity { ceilingCents, availableCents, reservedCents }` — [`schema.ts:472-476`](../../convex/schema.ts).

- **Invariant**: every leg ≥ 0 and `availableCents + reservedCents === ceilingCents` — `isValidCapacity`, [`transitions.ts:74-77`](../../convex/guarantees/transitions.ts). A row that violates it is **refused, not repaired** (`CAPACITY_INVARIANT_BROKEN`).
- **Only cover and its reversal move capacity.** Arrears, verification, eviction and every close reason except `dispute_reversal` leave it alone.
- **Reserve on cover** — `reserveCoverCapacity` ([`transitions.ts:209-260`](../../convex/guarantees/transitions.ts)), called by `commitCover` ([`coverOperations/mutations.ts:212-217`](../../convex/coverOperations/mutations.ts)): `appliedCents = min(availableCents, amountCents)` (`:232`), moved from `available` to `reserved`. The applied figure — not the requested one — is stored on the notice as `resolution.appliedCoverCents` and on the ledger row as `appliedCents`, and audited as `guarantee.capacity_reserved { requestedCents, appliedCents }`. Because of this clamp, the admin cover dialog shows claimed / remaining / to-be-drawn before the operator confirms, and the batch preview shares one remaining ceiling across notices of the same guarantee.
- **Exact release on `close(dispute_reversal)`** — staff `close` with that reason calls `closeAsDisputeReversal` ([`transitions.ts:368-433`](../../convex/guarantees/transitions.ts); routed at [`guarantees/mutations.ts:203-218`](../../convex/guarantees/mutations.ts)). From `cover_committed` it sums `resolution.appliedCoverCents` over the guarantee's `cover_committed` notices (`sumAppliedCover`, `:342-354`) and requires `sum(appliedCoverCents) === reservedCents`; a mismatch is `CAPACITY_INVARIANT_BROKEN`, refused before the first write (`:396-403`). It then calls `releaseCoverCapacity({ appliedCents })` ([`transitions.ts:272-328`](../../convex/guarantees/transitions.ts)), which gives back **exactly the stored figure** (more than is reserved → `RELEASE_EXCEEDS_RESERVED`) and emits `guarantee.capacity_released`, and only then runs the transition, so the `guarantee.transitioned` row stamps the restored capacity (`:405-426`). From `default_verified` nothing was drawn, so it closes with no release (`:382-394`). Reversing the applied number rather than a recomputed one is what keeps `available + reserved === ceiling` exact.
- **Every other close reason keeps the cents reserved.** A covered guarantee closed for `end_of_lease`, `rescission`, `abandonment`, `death` — or for `eviction` from `in_eviction` — leaves `reservedCents` held: that cover was paid out, and burning it waits for the receivable ledger, not a close ([`guarantees/mutations.ts:191-195`](../../convex/guarantees/mutations.ts)).
- `INVALID_AMOUNT` for a non-integer or negative amount (`:217-223`, `:280-286`).
- `reservedCents` is a high-water mark of what was drawn and not reversed; there is no `consumed` leg until the recourse-receivable ledger exists ([ADR 0007 § 9](decisions/0007-lease-guarantee-split.md)).
- A capacity write is an aggregate write: `writeCapacity` patches the row and rewrites `insuredCentsPlatform` together (`:439-449`).

`terms` (immutable snapshot taken at `create`, refreshed only by `reprice`) — [`schema.ts:453-471`](../../convex/schema.ts): `productSlug, plan, rentCents, feeCents, taxaFeeCents, prestamistaFeeCents, oneTimeActivationFeeCents, commissionRate, prestamistaCommissionRate, coverageCeilingMultiplier, exitCostMultiplier, coverageCeilingCents, exitCostCapCents, appliedAt`. Three names are Portuguese: `taxaFeeCents` is the guarantee fee proper (rent × the tenant's credit-tier rate, _taxa_ = fee); `prestamistaFeeCents` is the premium for the optional credit-life cover (_seguro prestamista_) sold on the Plus plan, `0` otherwise; `prestamistaCommissionRate` is the broker commission rate on that premium. `feeCents` is their sum ([`pricing.ts:55-66`](../../convex/guarantees/pricing.ts)). Platform exposure per guarantee = `capacity.availableCents + terms.exitCostCapCents` ([`aggregate.ts`](../../convex/guarantees/aggregate.ts) `insuredCentsPlatform`).

## 9. Idempotency

The notice is the unit of idempotency for the default path ([ADR 0007 § 7](decisions/0007-lease-guarantee-split.md)): `openNotice` refuses a second `open` notice for the same `(guarantee, rentDueDate)`, and every state-changing mutation re-runs `assertTransition`, so a replayed request lands on `SELF_TRANSITION` (or the notice's `TERMINAL_STATE`) and writes nothing. Cover adds one explicit key on top: `(guaranteeId, coveragePeriod)` on the ledger (§ 6.3), so a second notice for the same billing month cannot mint a second payout, and `staffMarkCoverExecuted` refuses an already-executed row. A concurrent pair of `openNotice` calls for the same due date is not serialised by a unique constraint (Convex has none): both can pass the duplicate check and both insert. The fix is an optimistic-concurrency retry or a serialisation lock; at pilot volumes, with one agency operator filing per guarantee, the race is accepted rather than engineered around.

## 10. Deviations from the protocol scenarios document

The machine was derived from `docs/operation/contract-default-scenarios.md` in the `mutav` protocol repo (`mutav-finance/mutav#185`). That repo is private, so reviewers cannot open it; its essential content is a scenario catalogue for defaults and cures (arrears, verification, cover, cure-after-cover, repayment plans, write-off, eviction, death) plus the capacity-policy comparison summarised in § 7. The code comment at [`machine.ts:30-35`](../../convex/guarantees/machine.ts) names as the source of truth for the edges. The shipped implementation departs from that document in these places; where the two disagree, **this document describes what runs**.

| Scenarios doc                                                                                                                                            | Shipped                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A second machine for the **receivable** (`pending → in_installments → partially_paid → settled / written_off`) in `convex/receivables/`, `convex/cover/` | Not built. Cover is recorded in the `coverOperations` ledger (`recorded → executed`, § 6.3) and linked from the notice (`resolution.coverOperationId`, `appliedCoverCents`); the recourse-receivable ledger is ADR 0007 § 9 out-of-scope. |
