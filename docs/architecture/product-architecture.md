# Mutav — Product Architecture

> What the product does today, feature by feature, with the honest state of each one. Snapshot of `main` @ `58e72d5` and GitHub Project board #3 on 2026-09-16. The system view (apps, backend, external services, keys) is [`README.md`](README.md) + [`system-architecture.html`](system-architecture.html); this document is the _feature_ view — what a user can do, on which surface, and what is still inert, planned, or stage 2.

## How to read the states

| State            | Means                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Live**         | Deployed on `main`, backed by real Convex data, reachable by the user it is for                                    |
| **Partial**      | The screen is live but some of its actions are inert (no `onClick`, `disabled`, or no backend behind them)         |
| **Backend only** | A public Convex function exists and is tested, but nothing in `apps/` calls it — the capability has no operator UI |
| **UI only**      | A screen exists but reads hardcoded data or calls nothing                                                          |
| **Placeholder**  | A route that renders "coming soon"                                                                                 |
| **Planned**      | An issue exists; no code                                                                                           |
| **Stage 2**      | Deliberately out of pilot scope (`stage-2` label); the fund / investor / operator-runtime cluster                  |

Pilot scope is **agency + admin + LGPD** ([`#208`](https://github.com/mutav-finance/mutav-app/issues/208)); the investor portal and the operator runtime are stage 2 ([`#235`](https://github.com/mutav-finance/mutav-app/issues/235), [`#236`](https://github.com/mutav-finance/mutav-app/issues/236)).

## The product in one paragraph

Mutav sells a **rental guarantee** (fiança locatícia) to real-estate agencies. The agency opens a guarantee against a lease through a wizard; Mutav scores the tenant, prices the guarantee from a product's rate table, and snapshots the terms. The agency is billed monthly for every in-force guarantee; the tenant pays each invoice through a link (Pix via Etherfuse, or Stellar). When a tenant defaults, the agency opens a delinquency notice, Mutav staff verify it and commit cover from a reserve, and the guarantee walks the seven-state lifecycle to closure. A public-facing transparency view shows the book and the on-chain reserve. Investors funding the reserve are stage 2.

## The gaps that decide whether the pilot can run

Ranked by how directly each blocks a real agency writing a real guarantee and getting paid.

1. **No activation path.** `create` writes `drafted`; `activate` exists (agency-scoped, tested) but no screen, button, email link or script calls it. Every `active` guarantee in every environment came from the seed. Story 1.9 (e-signature) is the intended trigger, but it is `XL` and unscheduled until S6 — a manual "Activate" on the detail page is the bridge — [`#328`](https://github.com/mutav-finance/mutav-app/issues/328), `priority:high`.
2. **The detail page is half inert.** "Open delinquency", "Track delinquencies", edit / duplicate / archive, and document upload are rendered but do nothing ([`#291`](https://github.com/mutav-finance/mutav-app/issues/291), [`#294`](https://github.com/mutav-finance/mutav-app/issues/294)).
3. **Notifications cover one moment.** Only "proposal created" fires; nothing on activation, invoice, overdue, notice, or onboarding decision. WhatsApp has no provider ([`#229`](https://github.com/mutav-finance/mutav-app/issues/229), [`#51`](https://github.com/mutav-finance/mutav-app/issues/51)).
4. **Pix is sandbox-only** and there is no boleto ([`#32`](https://github.com/mutav-finance/mutav-app/issues/32), [`#19`](https://github.com/mutav-finance/mutav-app/issues/19), [`#78`](https://github.com/mutav-finance/mutav-app/issues/78)). Stellar works but is not how a Brazilian tenant pays rent.
5. **Credit scoring is mock by default**, and CNPJ is always mock. Switching `SCORE_PROVIDER` to `cpfcnpj` / `bigdatacorp` is an env change plus a contract, not code — but the pricing that follows from it is still being corrected ([`#300`](https://github.com/mutav-finance/mutav-app/issues/300)).
6. **Cover never reaches the chain.** Staff "cover" moves Convex capacity and closes the notice; the on-chain `cover_default` and the admin multisig are unbuilt ([`#286`](https://github.com/mutav-finance/mutav-app/issues/286), [`#325`](https://github.com/mutav-finance/mutav-app/issues/325)).
7. **Transparency is not public.** The only transparency route is behind agency login ([`#168`](https://github.com/mutav-finance/mutav-app/issues/168)).
8. **Tenant PII is plaintext** ([`#94`](https://github.com/mutav-finance/mutav-app/issues/94), [`#95`](https://github.com/mutav-finance/mutav-app/issues/95)); the production Auth0 tenant is not cut ([`#119`](https://github.com/mutav-finance/mutav-app/issues/119)).
